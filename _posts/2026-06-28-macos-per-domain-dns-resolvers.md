Recently I needed to resolve certain private internal domains (belonging to an AWS Route 53 private hosted zone) using custom DNS servers while allowing every other domain to continue using my normal system DNS configuration.

My first instinct was to edit `/etc/resolv.conf`, but on macOS that isn’t the recommended approach. The file is often regenerated by the operating system, VPN clients, or network configuration changes, meaning manual edits often won't persist.

Instead, macOS provides a cleaner mechanism using the `/etc/resolver` directory.

## Configuration

Create the resolver directory if it doesn't already exist:

```
sudo mkdir -p /etc/resolver
```

Next, create a file named after the DNS suffix you want to resolve using custom DNS servers:

```
cd /etc/resolver
touch /etc/resolver/private.example.internal
```

The filename itself determines which DNS suffix this resolver applies to, so for this use case the file only needed to contain the nameservers:

```
nameserver 10.0.0.2
nameserver 10.1.0.2
```

Reload the macOS DNS resolver:

```
sudo killall -HUP mDNSResponder
```

Verify that the resolver has been registered:

```
scutil --dns
```

You should see output similar to:

```
resolver #8
  domain : private.example.internal
  nameserver[0] : 10.0.0.2
  nameserver[1] : 10.1.0.2
```

Finally, verify that name resolution works as expected:

```
dig somehost.private.example.internal
```

At this point, any hostname within `private.example.internal` will be resolved using the specified DNS servers, while all other domains continue using your normal system resolvers.

## Why This is a Good Approach

Using `/etc/resolver` keeps domain-specific DNS configuration isolated, persistent, and easy to understand. It avoids modifying global resolver settings and works well when switching between private environments and the public internet.
